### 1.1 Backend API Contract (existing, unchanged shape)

| Endpoint | Method | Permission | Purpose |
|----------|--------|-----------|---------|
| `/api/price-lists` | GET | auth | List all (after Stage 0: + embedded stats) |
| `/api/price-lists` | POST | `manage_prices` | Create `{name, is_default}` |
| `/api/price-lists/:id` | PUT | `manage_prices` | Rename / set default |
| `/api/price-lists/:id` | DELETE | `manage_prices` | Delete (400 if default; after Stage 0: 409 if referenced) |
| `/api/price-lists/:id/stats` | GET | auth | Per-list counts (kept for compat; frontend stops using it) |
| `/api/price-lists/:id/prices` | PUT | `manage_prices` | **NEW (Stage 0)** bulk price-set |
| `/api/services` | GET | auth | All services incl. `prices[]` (per-list) + `drugs[]` (`null` when empty) |
| `/api/services` | POST | `manage_services` | Create; returns bare row (no prices/drugs) → refetch |
| `/api/services/:id` | PUT | `manage_services` | Update; `prices` = UPSERT-only; `drugs` = full replace |
| `/api/services/:id` | DELETE | `manage_services` | Delete (after Stage 0: 409 if referenced) |
| `/api/pharmacy/drugs/shipments` | GET | auth | All drug shipments incl. `prices[]` (batch-scoped) |
| `/api/pharmacy/medical-supply-shipments` | GET | auth | All supply shipments incl. `prices[]` |
| `/api/pharmacy/drugs/cards` | GET | auth | Drug picker source for Service modal |

Wire notes: `lib/api.ts` auto-camelCases responses / snake_cases request bodies. `prices[].price` is numeric on list endpoints but **string** (`toFixed(2)`) on `GET/PUT /api/services/:id` — parse defensively in one place (`Number(price)`). `prices`/`drugs` can be `null` → normalize to `[]`.

## 2. Stage 0 — Backend Companion

### 2.1 `PUT /api/price-lists/:id/prices` (new)

- **File:** `src/app/routes/priceList.routes.ts` (route after `verifyToken` + `checkPermission("manage_prices")` + `auditLogger`), `src/app/controllers/PriceList.controller.ts`, `src/app/models/PriceList.model.ts`.
- **Body** (all sections optional; an entry's `price: null` = **remove** that price; entries with a missing `price` key are invalid):
  ```json
  {
    "services":       [{ "service_id": 1, "price": 100.5, "requires_prepayment": false, "prepayment_type": null, "prepayment_amount": null },
                       { "service_id": 2, "price": null }],
    "drugShipments":  [{ "shipment_id": 3, "price": 55, "requires_prepayment": true, "prepayment_type": "percentage", "prepayment_amount": 20 }],
    "supplyShipments":[{ "shipment_id": 7, "price": 30 },
                       { "shipment_id": 9, "price": null }]
  }
  ```
- **Semantics:** single `BEGIN/COMMIT` transaction. `price: null` → `DELETE FROM <ServicePrice|ShipmentPrice|MedicalSupplyShipmentPrice> WHERE entity_id = $1 AND pricelist_id = $2` (no-op if absent). Otherwise UPSERT per `(entity_id, pricelist_id)` — other lists' prices untouched. Supplies: no prepayment (mirror `MedicalSupplyShipmentPrice` usage).
- **Validation:** upsert entries — `price` numeric; services `price >= 0`, shipments `price > 0` (matches each domain's existing rules). Prepayment (services + drugs only): `prepayment_type` ∈ fixed|percentage, amount required when `requires_prepayment`, percentage 0–100, fixed ≥ 0 — same rules as `DrugShipment.model.updateShipment`. Removal entries — no other fields required/validated.
- **Response:** `200 { total_services: n, total_drugs: n, total_supplies: n, removed_prices: n }` (fresh stats for the list + removal count — lets the UI patch counts and build the toast without extra fetches). Errors: 400 invalid body, 404 list missing, 500 otherwise.
- **No DB schema changes anywhere in Stage 0** — all six items are query/route/controller logic over existing tables; deployment-safe, no migration step.

### 2.2 Batch stats on `GET /api/price-lists`

- Extend `PriceList.model.getAllServices`… i.e. `getAllPriceLists` to join/aggregate the three counts (`ServicePrice` rows; `ShipmentPrice`→`DrugShipment` qty>0; `MedicalSupplyShipmentPrice`→`MedicalSupplyShipment` qty>0) and return `total_services`, `total_drugs`, `total_supplies` per list. Keep `/:id/stats` route for backward compat.

### 2.3 FK-friendly deletes (409)

- `DELETE /api/services/:id`: pre-check `ActivePatientService` (is_active rows) and `BillDetail` references → `409 { error: "Cannot delete this service: it is used by N active patient service(s) and M bill line(s)." }`.
- `DELETE /api/price-lists/:id`: pre-check `Patient`, `PatientHistory`, `InsuranceCompany` → `409 { error: "Cannot delete this price list: N patient(s), M admission(s), K insurance company(ies) reference it." }`. Existing default-400 stays.

### 2.4 Service controller fixes

- `Service.controller.getServiceById`: guard `prices`/`drugs` `null` → `[]` (fixes 500 on price-less services; remove unguarded `.forEach`).
- `Service.model.updateService`: when `UPDATE` affects 0 rows → throw → controller returns **404** (currently 500).

### 2.5 Dead search routes

- `src/app/routes/service.routes.ts`: move `GET /search` and `GET /suggestions` **above** `GET /:id` (currently shadowed → 500/404). No behavior change for the React pages (they filter client-side).

### 2.6 Default-invariant guard

- `PriceList.model.updatePriceList`: if `is_default === false` and this row is currently the default → `400 { error: "Cannot unset the default price list. Set another list as default first." }`.

### 2.7 Backend tests (`src/app/tests/`, following `db.helper.ts` patterns)

- Bulk endpoint: upsert across all 3 sections; removal entries (`price: null`) delete only the target (entity, list) row and leave other lists untouched; mixed set+remove in one call; removal of absent price = no-op; blank/invalid entries rejected; prepayment validation errors; `manage_prices` allowed / other-permission user 403.
- Batch stats counts; FK 409s (service referenced by BillDetail; list referenced by Patient); default-unset 400; `getServiceById` with zero prices.
- Mind the test-schema drift: test `ServicePrice` declares `service_price_id SERIAL PK` **plus** composite `(service_id, pricelist_id)` (differs from prod schema) — seed via `db.helper.ts` (lists: Standard (default), VIP, Insurance; services priced in every list).

**Verified wire shapes for the Add Prices datasets** (confirm at implementation, but verified 2026-09-15):
- `GET /api/services` → elements `{ serviceId, name, serviceType, autoRenew, autoAddOnAdmission, prices: [{pricelistId, price, requiresPrepayment, prepaymentType, prepaymentAmount}] | null, drugs: [{serviceId, drugId, name}] | null }` — `prices`/`drugs` are SQL `null` when empty → normalize to `[]`; no `serviceId` inside `prices[]` items.
- `GET /api/pharmacy/drugs/shipments` (list-all) → elements = `DrugShipment`-shaped (`shipmentId, drugId, warehouseId, quantity, buyPrice, expiryDate, receivedDate, drugName, warehouseName, unitConversion`) + `prices: [{pricelistId, price, requiresPrepayment, prepaymentType, prepaymentAmount}] | null` — **no** `quantityInLargerUnit`, **no** `pricelistName`; includes out-of-stock rows → filter `quantity > 0` client-side. Define PriceLists-local view types (existing `DrugShipment` type in `_shared/pharmacy/types.ts` doesn't quite match list-all).
- `GET /api/pharmacy/medical-supply-shipments` (list-all) → elements `{ shipmentId, supplyId, warehouseId, quantity, buyPrice, expiryDate, ..., supplyName, warehouseName, prices: [{pricelistId, price}] }` (no prepayment fields) — N+1 pricing query server-side; filter `quantity > 0` client-side.

Key behaviors:
- **Page skeleton:** `"use client"`, `useTranslation()` + `useEnsureNamespace("priceLists")` (idempotent; namespaces/routes/breadcrumbs already registered). PageHeader eyebrow `t("sidebar.priceLists")`, actions = create button.
- **Load:** `listPriceLists` only (stats embedded — no N+1). `AddPricesModal` lazy-loads its 3 datasets on open (`Promise.all` of services + both shipment lists), client-side search per tab (drugs/supplies also match warehouse name), filter shipments to `quantity > 0`.
- **Card price states:** unpriced → priced ("Price Set" badge, accent border) → **marked-for-removal** (danger badge `priceWillBeRemoved`, inputs disabled/cleared, undo restores previous values). Removal is an explicit Trash2 ghost icon button, only enabled on priced cards — not field-clearing (Decision #11). No per-removal confirm; save is the explicit commit.
- **Save prices:** collect entries → upserts (non-blank, changed or new) + removals (`price: null`) → `setPricesForList` → success toast `{{set}} set, {{removed}} removed` (all counts i18n'd, incl. supplies) using response counts, refresh list hook (response stats patch card counts).
- **Post-create flow:** after create, ConfirmDialog "Add Prices Now?" (priceLists.messages.addPricesNow*) → opens modal for the new list.
- **Delete:** `ConfirmDialog` variant danger; description switches to `deleteWithAssociationsWarning` ({{services}}/{{drugs}} interpolation; extend text to include supplies count) when counts > 0; on `409` show server message via toast.
- **Default handling:** card Delete hidden for default list; modal blocks unsetting (Decision #5); 400 from API surfaced as toast with server message.
- **Permission note:** bulk endpoint is `manage_prices` — the page's own permission — so the manage_prices-only user gap is closed by Stage 0.

i18n: extend existing `src/renderer/src/locales/priceLists.{en,ar}.json` (structure already mirrors legacy keys; add: `actions.removePrice` + aria, `status.priceWillBeRemoved`, save toast with `{{set}}`/`{{removed}}` interpolation, delete-warning supplies interpolation, tab count-badge label, default-guard error, empty-tab states). Namespace + route + breadcrumb already registered.
