### 1.1 Backend API Contract (existing — no changes except price removal)

| Endpoint | Method | Permission | Purpose |
|----------|--------|-----------|---------|
| `/api/employees` | GET | `manage_employees` | All employees (all types). Optional `?type=` filter (unused — filter client-side). |
| `/api/employees` | POST | adminOnly | Create employee (`CreateEmployeeDTO`). |
| `/api/employees/:id` | PUT | adminOnly | Partial update (body keys are read generically → snake_case required; `lib/api.ts` `toSnake` handles this). |
| `/api/employees/:id` | DELETE | adminOnly | Hard delete (cascades: clock-ins/payments FK behavior per schema — no 409 handling exists; surface server errors as toasts). |
| `/api/doctors` | GET | auth (any user) | Doctors incl. doctor-table fields. |
| `/api/doctors` | POST | adminOnly | Create (Employee + Doctor rows in a transaction) + service-price upserts after. |
| `/api/doctors/:id` | PUT | adminOnly | Update employee+doctor fields + servicePrices upsert/delete (after backend change). |
| `/api/doctors/:id` | DELETE | adminOnly | Delete Doctor + Employee rows. |
| `/api/doctors/:id/services/prices` | GET | auth | `{doctorId, serviceId, serviceName, price}[]` for pre-fill. |
| `/api/employee-payments` | GET | `manage_payments` | **All** payments (replaces legacy `unpaid-system` + per-employee fetches). |
| `/api/employee-payments` | POST | `manage_payments` | Create manual payment (stamps `paidByUserId` from token). |
| `/api/employee-payments/:id/paid` | PUT | `manage_payments` | Mark paid (sets `paidByUserId` + `paidTimestamp`). |
| `/api/employee-payments/:id/void` | PUT | `manage_payments` | Void. |
| `/api/services` | GET | auth | Service list for the doctor service-prices grid (reuse `listServices` from `@/pages/Services/api`). |
| `/api/users/name/:id` | GET | auth | Username for `paidBy` resolution. |

**Wire-shape notes (camelCase after `toCamel`):**
- Employee: `employeeId, name, phone?, isFacilityEmployee, isActive, hireDate, employeeType, basePay?, extraAmount?, extraPaymentType? ("none"|"per_patient"|"income"), perPatientPaymentType? ("fixed"|"percentage"), percentageScope? ("before_deductions"|"after_deductions"), needClockIn, shiftType? ("morning"|"night"), shiftStartTime?, shiftEndTime?` — `shiftStartTime/EndTime` are `"HH:mm"` strings.
- Doctor adds: `doctorType ("attending"|"supervising"|"referring"|"outside"), dailyPay?, perPatientPay?, paymentCalculation ("fixed"|"per_patient"|"both"), referralBonus?`.
- **Doctor payload must send BOTH mirrors** (legacy parity, required by `Doctor.model`): `dailyPay` **and** `basePay` (same value); `paymentCalculation` **and** `extraPaymentType` (same value). This is the wire contract, not a bug — do not "fix" it.
- Payment: `paymentId, employeeId, paymentAmount, extraPaymentType?, paymentType ("manual"|"bonus"|"overtime"|system types e.g. "service"|"referral"), percentageScope?, extraAmount?, isPaid, isVoid, issuedTimestamp, paidTimestamp?, paidByUserId?`. Display total = `paymentAmount + extraAmount` with `(+extra)` breakdown subtext (parity).
- `GET /api/services` prices/drugs arrays can be `null` → normalize (reuse `normalizeService` helper from `@/pages/_shared/services/types`).

## 3. Key Behaviors

- **Page skeleton:** `"use client"`, `useTranslation()` + `useEnsureNamespace("employees")` (idempotent; ns/routes/breadcrumbs already registered — remove only the `/doctors` breadcrumb entry). `PageHeader` eyebrow `t("sidebar.employees")`, no page-level action button (create lives per tab).
- **Tabs:** shadcn `Tabs` bound to `?tab=` (`employees` | `doctors` | `nurses` | `payments`); invalid/missing → `employees`. `DirectionProvider` already wraps the app (Radix Tabs honor RTL).
- **Load:** `useEmployees` fires on mount (all three staff lists come from the same fetch — legacy fetched `/api/employees` once and filtered by `employeeType` per tab). Doctors additionally from `GET /api/doctors` (the employee list does NOT include doctor-table fields like `doctorType`/`dailyPay`). Payment hook fires only when the user has `manage_payments` (`usePermission().hasPermission("manage_payments")`).
- **Tab refresh:** switching to a tab refetches its data (legacy `shown.bs.tab` behavior) — implement via an effect keyed on the active tab + nonce.
- **Smart filter toolbar (per staff tab):** `EmployeeFilterToolbar` — debounced search + status filter chips (All / Active / Inactive) + shift-type select (+ doctor-type select on the Doctors tab). All client-side. Legacy always-visible date-range inputs are **dropped** from the staff tabs — issued-date filtering lives on the Payments tab only.
- **Employees/Nurses tables:** columns per legacy (name, type, hire date, base pay, shift type, extra payment summary, active) upgraded per the UX package: sortable name/hire-date/pay columns (DataTable controlled sort), type badge, active/inactive `Badge` with icon (never bare ✓/✗ text), money cells `tabular-nums`, base pay shown only with `manage_payments` (else `—` with tooltip "requires payments permission"). Row actions as icon buttons with tooltips + `aria-label`: View (opens Sheet — everyone), Edit + Delete (Admin only), Create Payment (`manage_payments`). Row click also opens the Sheet.
- **Doctors table:** same treatment; doctor-type badge, daily pay, per-patient pay (fixed → currency, percentage → `N%`).
- **Employee detail Sheet (replaces legacy inline payment sub-rows):** opens from row click / View action. Sections: profile summary (type badge, phone, hire date, shift block, compensation summary — compensation values gated by `manage_payments`), then full payment history for that employee — filtered client-side from the bulk payments fetch (no extra request), newest first, status badge + amount breakdown (`total` with `(+extra)` subtext) + inline Mark Paid / Void per row (`manage_payments`, with confirms). Header actions: Edit (admin), Create Payment (`manage_payments`). Mobile/narrow: full-screen below `sm` per design.md §6.4.
- **Payments tab (work-queue polish):** client-side equivalent of legacy `unpaid-system` (`!isPaid && !isVoid && paidByUserId == null`, known employees only), **oldest-first** ordering. Toolbar: date-range filter as a Popover-hosted range picker (replaces raw datetime inputs) + Clear. Grouped by employee: expandable rows showing totalAmount (`tabular-nums`), type label, date range; bulk Mark All Paid / Void All grouped in a `DropdownMenu` with confirms → sequential `PUT` per payment → refresh + toast. Expanded row lists each payment (status badge, breakdown, issued date) with Mark Paid / Void. Employees with zero matching payments omitted (parity).
- **Paid-by names:** `useEmployeePayments` collects unique `paidByUserId`s from paid rows and resolves them through a cached `resolveUserNames` map (dedup + in-flight dedup); failures surface as `-`.
- **EmployeeModal (sectioned form per design.md §6.3):**
  - Open modes: create (pre-selected type from active tab: `other` on Employees, `nurse` on Nurses, `doctor` on Doctors) / edit (pre-filled from row or from the Sheet; type switches the doctor section).
  - Sections as fieldsets with legends: **Profile** (name required, phone optional-marked, hire date required, need clock-in checkbox, is active checkbox default checked, is facility employee checkbox — doctor section only), **Shift** (shift type select morning/night optional, shift start/end time required — `"HH:mm"`), **Compensation** (adaptive: nurse/other → base pay, extra payment type none/per_patient/income, extra amount visible when per_patient/income, per-patient payment type visible when per_patient, percentage scope visible when per_patient_payment_type=percentage OR extra_payment_type=income; doctor → doctor type required, daily pay, per-patient pay, referral bonus, payment calculation fixed/per_patient/both), **Service prices** (doctor only, collapsible: searchable list with per-service price inputs, blank = not set, explicit per-row remove for existing prices → payload `{serviceId, price: null}`; only changed/new entries sent — `servicePrices` omitted when unchanged).
  - Explicit "(optional)" markers on non-required fields; inline zod errors below fields; submit button shows `Loader2` spinner + disabled; on error focus first invalid field. Conditional fields render as stable groups (no pop-in jank).
  - On submit mirror `dailyPay`→`basePay` and `paymentCalculation`→`extraPaymentType` (§1.1). Employees create sends `isFacilityEmployee: true` (parity).
  - Payload: create `POST /api/employees` or `/api/doctors` (by type); edit `PUT :id` on the matching resource.
- **PaymentModal:** amount (required > 0), payment type (manual/bonus/overtime), extra payment type (none/per_patient/income) + conditional extra amount, percentage scope (visible when income). On save: `POST /api/employee-payments` → `PUT /:id/paid` (Decision #7) → refresh payments + employees → toast. Failure after create: surface error and still refresh.
- **Delete employee/doctor:** `ConfirmDialog` variant danger (`employees.messages.deleteConfirm*`); non-admin never sees the button; errors surface via toast with server message.
- **Toasts/errors:** sonner; all error paths `ApiError`-first (server message), fallback to i18n message keys. Success toasts use existing `employees.messages.*` keys.
- **Formatting:** `formatCurrency` (EGP), `formatDate`, `formatDateTime` from `lib/utils` with the active language (parity with legacy `i18n.format*`).

## 7. Future Work / Out of Scope

- Batch mark-paid/void endpoints (N sequential `PUT`s today; fine at current volume) — candidate for a future payments hardening pass alongside a `?status=` filter on `GET /api/employee-payments`.
- Server-side pagination/search for employees (legacy loads everything; data volumes are small).
- Wrapping doctor create/update + service-price writes in one backend transaction (today prices are written after the doctor transaction commits).
- Soft-delete / deactivate instead of hard delete for employees (schema-level change).
- Delete cascade surfacing (employee delete with payments/clock-ins relies on DB FK behavior; if 409s appear in practice, add explicit messaging).
